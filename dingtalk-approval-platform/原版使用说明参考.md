# 企业业务平台（局域网版）

## 启动与访问

- 双击 `启动局域网服务.bat`：一键启动前端和后端。
- 双击 `重启局域网服务.bat`：释放 5173、8000 端口后重新启动。
- 双击 `关闭局域网服务.bat`：关闭平台服务。
- 本机访问：`http://localhost:5173`
- 局域网访问：`http://本机IPv4地址:5173`

前端端口 5173，后端端口 8000。浏览器只需访问 5173，前端通过同域 `/api` 代理调用后端。

## 当前业务流程

`上传总表 → 解析实际部门 → 处理未知部门 → 勾选付款部门 → 生成附件 → 检测动态审批节点 → 选择手选节点审批人 → 预览全部流程 → 确认批量发起 → 查看结果`

- 不再固定生成 19 份。实际有 12 个付款分组就生成 12 份，有 25 个就生成 25 份。
- 原 19 条规则继续作为特殊合并规则。
- 无人员或费用明细的部门不会生成文件。
- 分组维度为“公司主体 + 付款部门”，跨公司同名部门分别生成。
- 未识别的新部门标记为“待归属”，完成归属后才能正式发起。
- 付款金额按日常餐补、宵夜餐补、出差餐补重新相加。
- 每个选中付款分组生成一份独立 Excel 明细表。

## 钉钉接入

### 表单赋值说明

流程预测使用钉钉新版接口，正式创建使用已与当前付款模板联调通过的旧版`/topapi/processinstance/create`接口。`部门分摊明细`按子控件名称填写；正式创建时会把“申请人部门”编码为部门 ID 数组，并补充模板标记为必填的`付款金额含税（元）`计算字段。

测试模板若设置了指定人员可发起，需确保`.env`中的固定发起人在模板“谁可以发起”范围内。平台在线预检会显示该范围提示。

1. 复制 `.env.example` 为 `.env`。
2. 在本机填写 AgentId、CorpId、固定发起人 UserId/DeptId、测试模板 processCode。
3. Client ID 与 Client Secret 只保存在 `.env`，不要发送到聊天或提交到版本库。
4. 在“钉钉接入”页面执行在线预检。
5. 测试模板联调通过后，再开启：
   - `DINGTALK_ATTACHMENT_ENABLED=true`
   - `DINGTALK_LIVE_SUBMIT_ENABLED=true`

批量审批默认同时处理 3 个付款分组。可在 `.env` 设置 `DINGTALK_BATCH_CONCURRENCY` 为 1 至 5；建议保持 3，以平衡钉钉限流风险和处理速度。提交期间可在“审批预览与提交”的进度窗口逐部门查看附件上传、路径校验和审批创建状态。

审批节点由平台按每个付款分组的表单值调用钉钉流程预测接口动态识别，不需要为新任务手工配置 `actionerKey`。`DINGTALK_ACTIONER_KEYS_JSON` 仅用于兼容旧任务。

### 手选审批节点准备

在钉钉“付款申请单-接口测试”模板中，可以分别建立以下手选审批节点：

- 项目/设计总监
- 项目经理
- 费用发生部门主管

进入每个节点的审批人设置，将审批人类型设为“发起人自选”，并在“可选人员范围”中明确选择允许的成员。不要保留为全公司或未限定范围。保存并发布模板后，重新生成附件或重新执行流程检测。

平台会读取钉钉预测结果中的 `actorSelectionRange`，只加载和展示范围内的人员。未设置范围、仅返回无法解析的部门范围，或选择了范围外人员时，审批预览会被阻止。固定节点以及未命中条件的分支不需要在平台中手选。

平台“付款资料”页面包含“手选节点人员范围”标签页，默认提供项目/设计总监、项目经理和费用发生部门主管三类节点。可以输入姓名或 UserId 搜索应用通讯录授权范围内的人员，添加多人后统一保存。节点名称需要与钉钉模板中的节点名称一致。

本地人员范围是平台提交前的额外安全限制：钉钉模板没有限定具体成员时使用本地范围；钉钉模板也限定了成员时，实际可选人员取两者交集。本地配置不能扩大钉钉模板原有权限。

附件上传使用钉钉官方 `spaceId` 流程。平台会自动获取固定发起人的 `unionId` 和审批钉盘空间，不需要在 `.env` 手工填写上传接口地址。

`DINGTALK_ORIGINATOR_DEPT_ID` 是流程发起和预测所使用的发起人所属部门；`DINGTALK_APPLICANT_DEPT_ID` 是表单“申请人部门”控件的值。两者相同时可将后者留空。选择“部门费用”时，平台只提交部门分摊明细，项目分摊明细保持未激活状态。

## 数据保存

- 上传文件：`data/uploads/`
- 输出文件：`data/outputs/`
- 任务、付款资料、部门归属和审批实例记录：`data/workflow.db`

SQLite 数据会在服务重启后恢复。已成功发起的审批不会被失败重试重复提交。

## 文件要求

支持上传具有授权、可编辑且未加密的 `.xlsx`、`.ods` 和 Apple Numbers `.numbers` 文件。

- `.ods` 和 `.numbers` 上传后会在本机服务中转换为标准 `.xlsx`，再进入相同的部门识别与金额校验流程。
- 多工作表或多表格文件会自动选择包含补贴总表必需表头的数据表。
- 付款汇总、部门明细和压缩包中的输出文件仍统一为 `.xlsx`。
- “本机 WPS / Microsoft Excel 授权导入”仍标记为“目前不可用”，且该入口只适用于 `.xlsx`。

## 旧版审批创建与完整审批链确认

本部署仅使用旧版 POST /topapi/processinstance/create 发起审批，不再切换新版创建接口，也不会在创建失败后自动换接口或自动重发创建请求。

### 两种提交模式

- **无手选节点：沿用模板模式。** 不发送整链审批人覆盖值，继续使用模板固定审批人和抄送配置。
- **有手选节点：完整审批链模式。** 根据本次表单的实际预测路径，依次整理固定节点、已选择的手选人员、财务等后续固定节点和抄送配置，使用旧接口的 approvers_v2 提交完整链条；不会只传三个手选人员而遗漏固定节点。
- 完整链条会在每条审批预览中展示，包括审批顺序、固定/手选来源、会签/或签/依次审批，以及开始/结束抄送。未选择的非必选节点标记为跳过。
- 该模式指定整条审批链，不是将手选人员按节点键补回原模板。手写签名、表单操作权限等模板高级设置不支持，确认窗口会明确提示。业务需要这些能力时，不应使用该模式发起。

### 更新后的操作步骤

1. 运行“重启局域网服务.bat”加载更新。本次没有依赖、端口或启动参数变化，现有启动、关闭和重启脚本仍适用。
2. 打开任务，重新检测钉钉审批路径。旧任务中缺少完整角色/顺序信息的预测不能直接提交。
3. 选择手选节点的审批人员；已配置人员范围、搜索弹窗和最近审批人功能继续保留。
4. 重新生成审批预览，逐条核对付款字段、完整审批人、审批顺序和抄送。
5. 点击“确认并批量发起”。含手选节点时，必须勾选已核对完整审批链及高级设置限制，才可确认发起。
6. 在进度窗口查看结果。已成功和“结果待确认”的记录不会再次创建；失败重试也必须重新确认，仅处理明确失败的部门。

### 提交前的保护

- 缺少或重复节点 ID、顺序无法确定、并行分支无法等价转换、无法解析的固定人员、未知节点类型、自动审批语义不兼容或超出旧接口人数/步骤限制时，阻止提交并说明原因。
- 流程中途抄送，或开始/结束抄送名单不同，无法安全保持原时机时也会阻止，不会省略抄送后继续创建。
- 手选人员必须满足必选/单选/多选和模板与本地可选人员范围约束。
- 预览保存表单及完整审批链指纹。金额、付款资料、人员或节点发生变化时必须重新检测/预览/确认。
- 上传附件后再次预测，节点签名或完整链条变化时终止该条创建。同一任务处理期间禁止并发编辑/提交。
- 正式创建只发送一次；创建超时或无法确认实例 ID 时记为“结果待确认”，请先在钉钉核对，不允许直接重试。

本次验证使用模拟接口与临时数据库，不代表真实钉钉已联调成功，也未创建任何真实审批。首次实际联调仍应使用测试模板。此前已创建成功的单据不会被更新改写，不要重复发起。
