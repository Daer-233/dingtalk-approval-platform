# 新接口测试副本使用说明

## 本副本定位

本目录为原“补贴付款拆分平台_局域网版”的独立副本。原目录保持旧接口，不受本次测试影响。
原项目目录没有可用于精确回滚的 Git 历史；本次恢复的是“新接口提交模式”，不是某个历史提交的完整快照。最新前端、动态审批节点、进度与防重复功能予以保留。

## 运行方式

1. 双击本目录的“启动局域网服务.bat”。
2. 本机前端：`http://localhost:5174`；后端：`http://127.0.0.1:8011`。
3. 手机与电脑在同一局域网时，使用电脑的局域网 IP 加端口 5174。
4. 关闭和重启请使用本目录内对应脚本，副本只处理 5174/8011，原版端口不变。
5. 副本使用自己的 .venv、data/workflow.db 和结果目录。配置已复制，但没有复制原任务及成功审批记录。

## 新接口提交方式

仅调用 POST /v1.0/workflow/processInstances。手选审批人通过 targetSelectActioners 的 actionerKey/actionerUserIds 绑定。固定节点与抄送沿用模板，不发送完整 approvers 覆盖模板，也不自动回退旧创建接口。创建超时结果不明时保持“待确认”，不得直接重复创建。

付款金额含税（元）的 CalculateField 在本模式中省略，交给模板计算。申请人部门、明细、发票及附件继续按 Schema 序列化。

## 正式提交开关

.env 中 DINGTALK_LIVE_SUBMIT_ENABLED=false。为避免误发，网页正式提交保持关闭。本次一次性测试只在测试进程内临时打开开关，没有修改 .env。
不要把 Client Secret 或 accessToken 发到聊天或提交到代码仓库。

## 本次测试

详见“新接口测试报告.md”。一次性脚本 scripts/test_modern_live.py 已执行，output/modern_create_once_guard.json 会阻止再次发起及覆盖已保存结果，请勿删除该保护记录来反复提交。
测试请求和 Schema 含内部部门/用户信息，只用于本机排查；提交给钉钉客服前应脱敏。

## 自动化检查

后端：.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
前端：进入 frontend 后运行 npm run build。
旧接口专用测试保留在 tests_legacy_reference；当前 tests 覆盖新接口及通用功能，不把旧接口行为的断言误用在新版中。

原版详细操作说明见“原版使用说明参考.md”。
